# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 8. Search Engine --- архитектура поисковой системы

------------------------------------------------------------------------

# Введение

По мере роста Showcase Studio количество демонстрационных сцен неизбежно
увеличивается. Если на ранних этапах разработчик может найти нужный
пример вручную, то при наличии сотен и тысяч демонстраций главным
инструментом становится поисковая система.

Search Engine в Showcase Studio --- это не обычное текстовое поле. Это
отдельная подсистема, обеспечивающая быстрый доступ к знаниям независимо
от структуры дерева категорий.

------------------------------------------------------------------------

# Цели поисковой системы

Поиск должен:

-   находить сцену за несколько символов;
-   работать мгновенно;
-   учитывать контекст запроса;
-   понимать синонимы;
-   искать одновременно в нескольких источниках данных;
-   ранжировать результаты по релевантности.

------------------------------------------------------------------------

# Источники данных

Поиск выполняется одновременно по нескольким индексам:

-   названию сцены;
-   идентификатору;
-   категории;
-   тегам;
-   краткому описанию;
-   полной документации;
-   списку используемых классов;
-   версии API.

Каждый индекс имеет собственный вес при ранжировании.

------------------------------------------------------------------------

# Индексирование

После регистрации сцен Registry передает их метаданные Search Engine.

Формируется внутренний индекс, содержащий:

-   ключевые слова;
-   нормализованный текст;
-   ссылки на сцену;
-   список тегов;
-   дополнительные признаки.

Индекс строится один раз при запуске и обновляется при регистрации новых
пакетов.

------------------------------------------------------------------------

# Полнотекстовый поиск

Полнотекстовый поиск позволяет находить демонстрации не только по
названию, но и по описанию.

Например, запрос:

    миллион строк

может вернуть сцену:

    Performance / Million Rows

даже если слова отсутствуют в её названии.

------------------------------------------------------------------------

# Поиск по API

Дополнительно индексируются названия основных классов библиотеки.

Например:

    TUniListView

или

    TUniColumn

Поиск сразу покажет все сцены, использующие данный класс.

------------------------------------------------------------------------

# Поиск по тегам

Теги позволяют объединять разные демонстрации общей тематикой.

Например:

    virtual

вернет:

-   Virtual Mode;
-   Virtual Data Source;
-   Million Rows;
-   Lazy Loading.

------------------------------------------------------------------------

# Ранжирование

При совпадении нескольких сцен результаты сортируются по релевантности.

Приоритет может быть следующим:

1.  точное совпадение названия;
2.  совпадение идентификатора;
3.  совпадение тегов;
4.  совпадение категории;
5.  совпадение текста документации.

Такой порядок делает поиск предсказуемым.

------------------------------------------------------------------------

# Автодополнение

По мере ввода текста Search Engine отображает список возможных
совпадений.

Это позволяет открыть нужную сцену, не набирая запрос полностью.

------------------------------------------------------------------------

# Нечеткий поиск

Поисковая система должна быть устойчивой к небольшим ошибкам ввода.

Например:

    virtal

должно успешно находить

    Virtual Mode

Это особенно важно для длинных названий классов.

------------------------------------------------------------------------

# Производительность

Поиск никогда не должен обращаться к экземплярам сцен.

Работа ведется исключительно с индексами.

Даже при наличии нескольких тысяч демонстраций время отклика должно
оставаться практически мгновенным.

------------------------------------------------------------------------

# История запросов

Для удобства пользователя рекомендуется хранить историю последних
поисковых запросов.

Это позволяет быстро повторять часто используемые операции.

------------------------------------------------------------------------

# Фильтрация

Дополнительно поиск может поддерживать фильтры:

-   только API;
-   только документация;
-   только демонстрации;
-   только новые сцены;
-   только экспериментальные возможности.

------------------------------------------------------------------------

# Интеграция с Navigation

После выбора результата Search Engine не открывает сцену самостоятельно.

Он передает идентификатор Navigation, которая уже обращается к Scene
Host.

Это сохраняет слабую связанность архитектуры.

------------------------------------------------------------------------

# Лучшие практики

Рекомендуется:

-   индексировать только необходимые данные;
-   обновлять индекс инкрементально;
-   использовать единый механизм нормализации текста;
-   не выполнять тяжелые операции во время поиска;
-   разделять индексацию и отображение результатов.

------------------------------------------------------------------------

# Антипаттерны

Следует избегать:

-   линейного перебора всех сцен при каждом вводе символа;
-   обращения к файловой системе во время поиска;
-   создания экземпляров сцен для получения информации;
-   хранения дублирующихся индексов без необходимости.

------------------------------------------------------------------------

# Итоги

Search Engine превращает Showcase Studio в полноценную базу знаний.
Благодаря полнотекстовому поиску, тегам, индексированию API и
интеллектуальному ранжированию разработчик может мгновенно находить
нужные демонстрации независимо от размера проекта.

Следующая глава будет посвящена системе тем оформления Showcase Studio:
архитектуре Theme Manager, переключению тем, динамическому применению
стилей и рекомендациям по созданию собственных тем.
