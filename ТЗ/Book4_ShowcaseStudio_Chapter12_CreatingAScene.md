# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 12. Creating a Showcase Scene --- разработка собственной демонстрационной сцены

------------------------------------------------------------------------

# Введение

Главная ценность Showcase Studio заключается в том, что добавление новой
демонстрации должно быть максимально простым и предсказуемым. Независимо
от сложности примера каждая сцена создаётся по единому шаблону и
автоматически интегрируется со всеми подсистемами платформы.

------------------------------------------------------------------------

# Цели архитектуры

Процесс разработки новой сцены должен:

-   занимать минимум времени;
-   не требовать изменения ядра;
-   автоматически интегрироваться с Registry;
-   отображаться в Navigation;
-   индексироваться Search Engine;
-   поддерживать Documentation System;
-   работать с Diagnostics Framework;
-   соответствовать единому стилю Showcase.

------------------------------------------------------------------------

# Структура сцены

Рекомендуемый состав:

    Scene
     ├─ Main Unit
     ├─ View
     ├─ Resources
     ├─ Documentation.md
     ├─ TestData
     └─ Registration

Каждая сцена представляет собой полностью автономный модуль.

------------------------------------------------------------------------

# Ответственность сцены

Сцена отвечает только за демонстрацию одной возможности библиотеки.

Она не должна:

-   изменять глобальные настройки;
-   управлять навигацией;
-   создавать другие сцены;
-   обращаться к внутренним структурам Registry.

------------------------------------------------------------------------

# Жизненный цикл

Каждая новая сцена обязана поддерживать единый жизненный цикл:

1.  Create
2.  Initialize
3.  Activate
4.  Running
5.  Deactivate
6.  Destroy

Все переходы инициируются Scene Host.

------------------------------------------------------------------------

# Регистрация

После создания сцены необходимо зарегистрировать её.

Минимальные сведения:

-   идентификатор;
-   название;
-   категория;
-   теги;
-   фабрика;
-   описание.

После регистрации сцена автоматически становится доступной всем
подсистемам.

------------------------------------------------------------------------

# Документация

Для каждой новой сцены рекомендуется создать отдельный
Markdown-документ.

Он должен содержать:

-   цель демонстрации;
-   краткое описание;
-   основные возможности;
-   ограничения;
-   связанные сцены;
-   используемые классы.

------------------------------------------------------------------------

# Демонстрационные данные

Если сцена использует тестовые данные, они должны быть локальными.

Не рекомендуется:

-   обращаться к Интернету;
-   использовать внешние БД;
-   зависеть от файлов пользователя.

Все необходимые ресурсы должны поставляться вместе со сценой.

------------------------------------------------------------------------

# Интерфейс пользователя

Каждая демонстрация должна придерживаться общих правил:

-   единые отступы;
-   единая типографика;
-   единый стиль кнопок;
-   единая цветовая схема;
-   одинаковое расположение служебных элементов.

Пользователь не должен замечать перехода между сценами.

------------------------------------------------------------------------

# Использование Theme Manager

Все цвета и размеры следует получать через Theme Manager.

Запрещается жёстко прописывать:

-   RGB-значения;
-   размеры шрифтов;
-   размеры отступов;
-   параметры оформления.

------------------------------------------------------------------------

# Интеграция с Diagnostics

Если сцена выполняет длительные операции, рекомендуется регистрировать:

-   время загрузки;
-   время подготовки данных;
-   количество отображаемых объектов;
-   объём памяти.

Это позволяет сравнивать различные реализации.

------------------------------------------------------------------------

# Производительность

Демонстрационная сцена должна открываться максимально быстро.

Тяжёлые операции рекомендуется:

-   выполнять лениво;
-   переносить после активации;
-   выполнять по требованию пользователя.

------------------------------------------------------------------------

# Обработка ошибок

Все исключения должны корректно отображаться через Diagnostics
Framework.

Не допускается аварийное завершение Showcase Studio из-за одной
демонстрации.

------------------------------------------------------------------------

# Проверочный список

Перед добавлением новой сцены рекомендуется проверить:

-   корректность регистрации;
-   наличие документации;
-   работу поиска;
-   отображение в Navigation;
-   корректность жизненного цикла;
-   отсутствие утечек памяти;
-   совместимость тем;
-   работу локализации.

------------------------------------------------------------------------

# Лучшие практики

Рекомендуется:

-   демонстрировать одну возможность;
-   использовать минимальный объём кода;
-   сопровождать пример пояснениями;
-   применять единый стиль оформления;
-   использовать реальные сценарии использования.

------------------------------------------------------------------------

# Антипаттерны

Следует избегать:

-   объединения нескольких тем в одной сцене;
-   скрытых зависимостей;
-   тяжёлой инициализации;
-   использования глобального состояния;
-   отсутствия документации.

------------------------------------------------------------------------

# Итоги

Создание новой демонстрационной сцены в Showcase Studio представляет
собой стандартизованный процесс. Единая архитектура обеспечивает
автоматическую интеграцию с Registry, Navigation, Search Engine,
Documentation System, Theme Manager и Diagnostics Framework, благодаря
чему каждая новая демонстрация становится естественной частью общей
экосистемы UniListView.

Следующая глава будет посвящена рекомендациям по проектированию
демонстраций, UX-принципам и правилам подготовки качественных
Showcase-сцен.
