# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 5. Scene Host --- контейнер и диспетчер демонстрационных сцен

------------------------------------------------------------------------

# Введение

Scene Host является центральным исполнительным модулем Showcase Studio.
Если Scene Registry отвечает на вопрос **«какие сцены существуют?»**, то
Scene Host отвечает на вопрос **«какая сцена сейчас работает?»**.

Host выступает посредником между пользовательским интерфейсом, Registry
и конкретной демонстрацией. Благодаря этому сами сцены ничего не знают о
навигации, дереве категорий, панели поиска или структуре главного окна.

------------------------------------------------------------------------

# Основные задачи

Scene Host отвечает за:

-   создание сцены;
-   размещение сцены в рабочей области;
-   активацию и деактивацию;
-   переключение между демонстрациями;
-   освобождение ресурсов;
-   кэширование экземпляров;
-   передачу событий жизненного цикла;
-   взаимодействие с системой диагностики.

Host никогда не содержит бизнес-логику конкретной демонстрации.

------------------------------------------------------------------------

# Архитектурное положение

    Navigation
          │
          ▼
    Scene Host
       │      │
       ▼      ▼
    Registry  Active Scene

Все запросы на открытие новой демонстрации проходят исключительно через
Host.

------------------------------------------------------------------------

# Последовательность открытия сцены

1.  Пользователь выбирает сцену.
2.  Navigation передает её идентификатор Host.
3.  Host обращается к Registry.
4.  Registry возвращает описание и фабрику.
5.  Host создает экземпляр либо получает его из кэша.
6.  Выполняется инициализация.
7.  Сцена размещается в рабочей области.
8.  Вызывается активация.
9.  Пользователь начинает работу.

------------------------------------------------------------------------

# Рабочая область

Host предоставляет единственную область, в которой отображается текущая
демонстрация.

Это позволяет:

-   использовать единый стиль;
-   выполнять масштабирование;
-   централизованно управлять темами;
-   быстро заменять одну сцену другой без пересоздания главного окна.

------------------------------------------------------------------------

# Переключение между сценами

Перед открытием новой сцены Host обязан:

-   завершить текущие операции;
-   вызвать деактивацию;
-   остановить таймеры;
-   снять подписки;
-   сохранить состояние при необходимости.

Только после этого создается следующая сцена.

------------------------------------------------------------------------

# Кэширование

В зависимости от политики Showcase возможны несколько режимов.

## Без кэша

Каждое открытие создает новый экземпляр.

Преимущества:

-   минимальное потребление памяти;
-   простота.

Недостаток --- повторная инициализация.

## Полный кэш

Все сцены сохраняются до завершения работы приложения.

Преимущества:

-   мгновенное переключение;
-   сохранение состояния.

Недостаток --- большее потребление памяти.

## LRU-кэш

Host хранит только ограниченное число последних сцен.

Этот режим рекомендуется для крупных Showcase.

------------------------------------------------------------------------

# Управление памятью

Host должен гарантировать отсутствие утечек.

При уничтожении сцены освобождаются:

-   визуальные компоненты;
-   изображения;
-   модели данных;
-   временные коллекции;
-   подписки;
-   таймеры;
-   диагностические объекты.

------------------------------------------------------------------------

# Передача глобальных сервисов

Вместо использования глобальных переменных Host предоставляет сцене
необходимые сервисы:

-   Theme Manager;
-   Logger;
-   Diagnostics;
-   Settings;
-   Localization;
-   Resource Manager.

Такой подход облегчает тестирование и сопровождение.

------------------------------------------------------------------------

# Работа с ошибками

Если создание сцены завершилось ошибкой, Host не должен завершать работу
Showcase Studio.

Вместо этого отображается диагностическая страница с информацией:

-   название сцены;
-   исключение;
-   стек вызовов (в режиме разработчика);
-   рекомендации по устранению.

------------------------------------------------------------------------

# Интеграция с диагностикой

Host является удобной точкой подключения профилирования.

Можно измерять:

-   время создания сцены;
-   время активации;
-   объем используемой памяти;
-   количество визуальных объектов;
-   длительность переключения.

Эти сведения помогают оптимизировать демонстрации.

------------------------------------------------------------------------

# Навигация назад

Host может поддерживать стек навигации.

    Basic List
        ↓
    Columns
        ↓
    Editing
        ↓
    Performance

Пользователь может быстро вернуться к предыдущей сцене без поиска её в
дереве.

------------------------------------------------------------------------

# Повторное использование

Сцена не должна самостоятельно создавать или уничтожать соседние сцены.

Все подобные операции централизованы внутри Host.

Это обеспечивает единообразное поведение всей платформы.

------------------------------------------------------------------------

# Лучшие практики

Рекомендуется:

-   минимизировать время открытия сцены;
-   выполнять тяжелые операции после активации;
-   использовать ленивую загрузку;
-   централизовать управление памятью;
-   не хранить ссылки на Scene Host внутри бизнес-логики компонентов;
-   использовать единый контракт жизненного цикла.

------------------------------------------------------------------------

# Антипаттерны

Следует избегать:

-   прямого создания сцен друг другом;
-   хранения глобальных экземпляров;
-   изменения Registry из сцены;
-   запуска фоновых задач без уведомления Host;
-   самостоятельного уничтожения собственной формы.

------------------------------------------------------------------------

# Итоги

Scene Host является диспетчером всей демонстрационной платформы. Именно
он превращает независимые сцены в единое приложение с согласованным
жизненным циклом, единым интерфейсом и предсказуемым поведением.

Следующая глава будет посвящена системе навигации Showcase Studio:
дереву категорий, поиску, избранному, истории открытия сцен и
пользовательским сценариям перемещения между демонстрациями.
