# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 4. Scene Registry --- система регистрации демонстраций

------------------------------------------------------------------------

# Введение

Scene Registry является центральным каталогом всех демонстрационных сцен
Showcase Studio.

Ни Navigation, ни Scene Host, ни Documentation не знают конкретных
классов демонстраций. Все взаимодействие осуществляется через Registry.

Это позволяет строить расширяемую архитектуру без жестких зависимостей
между модулями.

------------------------------------------------------------------------

# Назначение Registry

Registry отвечает за:

-   хранение списка сцен;
-   регистрацию новых демонстраций;
-   поиск по идентификатору;
-   поиск по категории;
-   поиск по тегам;
-   поиск по версии;
-   предоставление метаданных;
-   создание экземпляров через фабрику.

Registry не отображает сцены и не управляет их жизненным циклом.

------------------------------------------------------------------------

# Принцип работы

Во время запуска приложения каждая демонстрация регистрирует собственное
описание.

В результате Registry содержит только информацию:

-   ID;
-   Name;
-   Category;
-   Description;
-   Tags;
-   Author;
-   Version;
-   Factory;
-   Supported Platforms.

Экземпляров сцен при этом не существует.

------------------------------------------------------------------------

# Почему регистрация лучше списка форм

Во многих Demo-приложениях используется код наподобие:

``` pascal
case Index of
  0: ShowBasic;
  1: ShowColumns;
  2: ShowSelection;
end;
```

Подобный подход быстро перестает масштабироваться.

Registry избавляет систему от подобных конструкций.

------------------------------------------------------------------------

# Метаданные сцены

Каждая запись Registry должна содержать полный набор информации.

Минимальный состав:

-   уникальный идентификатор;
-   отображаемое название;
-   краткое описание;
-   категория;
-   уровень сложности;
-   версия появления;
-   автор;
-   список тегов.

Дополнительно могут храниться:

-   рекомендуемые сцены;
-   минимальная версия библиотеки;
-   экспериментальный статус;
-   признак устаревания.

------------------------------------------------------------------------

# Идентификатор

ID никогда не должен изменяться.

Даже если название сцены было изменено.

Например:

    basic.list
    columns.resize
    selection.multiple
    performance.virtual

ID используется:

-   навигацией;
-   системой поиска;
-   ссылками документации;
-   пользовательскими закладками.

------------------------------------------------------------------------

# Категории

Категории используются только для навигации.

Например:

    Getting Started
    Basic Controls
    Selection
    Columns
    Editing
    Virtual Mode
    Themes
    Performance
    Diagnostics

Одна сцена принадлежит одной основной категории.

------------------------------------------------------------------------

# Теги

Теги используются поисковой системой.

Например:

    selection
    checkbox
    keyboard
    mouse
    touch
    multiselect

Одна сцена может иметь десятки тегов.

Это позволяет быстро находить примеры независимо от структуры дерева.

------------------------------------------------------------------------

# Фабрика

Registry хранит не экземпляр сцены, а способ её создания.

Условно:

    SceneInfo.Factory -> CreateScene()

Host вызывает фабрику только в момент открытия сцены.

------------------------------------------------------------------------

# Автоматическая регистрация

Каждый модуль демонстрации самостоятельно регистрирует себя.

Добавление новой сцены состоит из трех действий:

1.  Создать класс.
2.  Добавить регистрацию.
3.  Добавить описание.

Никаких изменений существующих модулей не требуется.

------------------------------------------------------------------------

# Проверка уникальности

Registry обязан контролировать:

-   уникальность ID;
-   отсутствие дублирования имен;
-   корректность категорий;
-   корректность тегов;
-   наличие фабрики.

Ошибки должны обнаруживаться при запуске Showcase Studio.

------------------------------------------------------------------------

# Поиск

Registry предоставляет быстрые методы поиска:

-   по ID;
-   по категории;
-   по тегу;
-   по части названия;
-   по версии;
-   по уровню сложности.

Поиск не зависит от пользовательского интерфейса.

------------------------------------------------------------------------

# Связанные сцены

Для каждой демонстрации может быть определён список связанных примеров.

Например:

    Columns

может ссылаться на

-   Column Resize;
-   Column Reorder;
-   Frozen Columns;
-   Column Templates.

Это превращает Showcase в связанную систему знаний.

------------------------------------------------------------------------

# Расширяемость

Архитектура Registry должна позволять подключать новые пакеты
демонстраций без изменения ядра.

Например:

-   Core Showcase;
-   Professional Showcase;
-   Enterprise Showcase;
-   Internal Showcase.

Все они регистрируются одинаковым способом.

------------------------------------------------------------------------

# Отладка

В режиме диагностики Registry может выводить:

-   количество сцен;
-   категории;
-   количество тегов;
-   дублирующиеся идентификаторы;
-   отсутствующие описания;
-   неподдерживаемые платформы.

Это значительно облегчает сопровождение проекта.

------------------------------------------------------------------------

# Лучшие практики

Рекомендуется:

-   использовать стабильные ID;
-   делать краткие названия;
-   писать информативные описания;
-   использовать единый стиль тегов;
-   не хранить состояние сцен внутри Registry;
-   отделять данные регистрации от логики отображения.

------------------------------------------------------------------------

# Итоги

Scene Registry является фундаментом Showcase Studio.

Он обеспечивает слабую связанность компонентов, автоматическое
обнаружение демонстраций, масштабируемость проекта и удобную навигацию
по сотням сцен.

Следующая глава будет посвящена Scene Host --- модулю, который отвечает
за создание, размещение, активацию и переключение демонстрационных сцен.
