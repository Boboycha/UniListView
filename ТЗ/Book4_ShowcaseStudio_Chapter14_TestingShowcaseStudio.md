# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 14. Testing Showcase Studio --- тестирование демонстрационной платформы

------------------------------------------------------------------------

# Введение

Showcase Studio является частью продукта UniListView. Следовательно, он
должен тестироваться с тем же уровнем строгости, что и сама библиотека.
Любая демонстрационная сцена --- это одновременно пример использования
API и тест его работоспособности.

Хорошо организованная система тестирования позволяет обнаруживать ошибки
ещё до выпуска новой версии библиотеки.

------------------------------------------------------------------------

# Цели тестирования

Тестирование Showcase Studio должно гарантировать:

-   корректную регистрацию сцен;
-   отсутствие ошибок открытия;
-   правильный жизненный цикл;
-   стабильную работу навигации;
-   корректность документации;
-   совместимость между версиями;
-   отсутствие утечек памяти;
-   одинаковое поведение на всех поддерживаемых платформах.

------------------------------------------------------------------------

# Пирамида тестирования

Рекомендуется использовать несколько уровней проверки.

                 UI Tests
              Integration Tests
               Scene Smoke Tests
                 Unit Tests

Каждый уровень решает собственные задачи.

------------------------------------------------------------------------

# Smoke-тесты

Каждая демонстрационная сцена должна автоматически проходить минимальную
проверку.

Типичный сценарий:

1.  регистрация;
2.  создание экземпляра;
3.  инициализация;
4.  активация;
5.  деактивация;
6.  уничтожение.

Если хотя бы один этап завершается ошибкой, сцена считается неисправной.

------------------------------------------------------------------------

# Проверка Registry

Автоматически контролируются:

-   уникальность идентификаторов;
-   отсутствие пустых названий;
-   корректность категорий;
-   наличие фабрики;
-   наличие документации;
-   корректность тегов.

Такая проверка выполняется при запуске тестового набора.

------------------------------------------------------------------------

# Проверка Navigation

Навигация должна подтверждать:

-   доступность каждой сцены;
-   корректное дерево категорий;
-   отсутствие битых ссылок;
-   работу истории;
-   корректность избранного;
-   полнотекстовый поиск.

------------------------------------------------------------------------

# Проверка Documentation

Для каждой сцены необходимо убедиться, что:

-   существует Markdown-документ;
-   отсутствуют битые ссылки;
-   заполнены обязательные разделы;
-   описание соответствует демонстрации.

Документация рассматривается как часть продукта.

------------------------------------------------------------------------

# Проверка ресурсов

Следует автоматически проверять наличие:

-   изображений;
-   SVG;
-   иконок;
-   локализации;
-   тестовых данных;
-   встроенных файлов.

Отсутствующий ресурс должен обнаруживаться до публикации.

------------------------------------------------------------------------

# Проверка жизненного цикла

После закрытия сцены тест подтверждает:

-   освобождение памяти;
-   остановку таймеров;
-   отсутствие активных подписок;
-   отсутствие фоновых задач;
-   корректное завершение диагностики.

------------------------------------------------------------------------

# Производительные тесты

Отдельный набор тестов измеряет:

-   время открытия;
-   время первой отрисовки;
-   объём памяти;
-   скорость переключения сцен;
-   FPS тяжёлых демонстраций.

Полученные показатели сравниваются с предыдущими версиями.

------------------------------------------------------------------------

# Регрессионные тесты

Каждая найденная ошибка должна сопровождаться отдельным тестом.

После исправления тест остаётся в наборе и предотвращает повторное
появление проблемы.

------------------------------------------------------------------------

# CI/CD

При каждой сборке рекомендуется автоматически выполнять:

1.  компиляцию Showcase;
2.  регистрацию всех сцен;
3.  Smoke-тесты;
4.  тестирование поиска;
5.  проверку документации;
6.  проверку ресурсов;
7.  формирование отчёта.

Сборка считается успешной только после прохождения всех этапов.

------------------------------------------------------------------------

# Матрица платформ

По возможности тестирование выполняется на всех поддерживаемых системах:

-   Windows;
-   Linux;
-   Android;
-   macOS;
-   iOS.

Это позволяет обнаруживать платформозависимые ошибки заранее.

------------------------------------------------------------------------

# Контроль качества

Перед публикацией новой версии рекомендуется проверить:

-   отсутствие необработанных исключений;
-   отсутствие устаревших сцен;
-   соответствие документации;
-   корректность локализации;
-   совместимость тем оформления;
-   стабильность навигации.

------------------------------------------------------------------------

# Лучшие практики

Рекомендуется:

-   автоматизировать максимальное число проверок;
-   запускать тесты при каждом изменении;
-   хранить тесты рядом с демонстрациями;
-   измерять производительность регулярно;
-   не публиковать сцены без автоматических проверок.

------------------------------------------------------------------------

# Антипаттерны

Следует избегать:

-   ручной проверки сотен сцен;
-   отсутствия smoke-тестов;
-   публикации демонстраций без документации;
-   игнорирования предупреждений диагностики;
-   хранения тестовых данных вне репозитория.

------------------------------------------------------------------------

# Критерии готовности сцены

Сцена считается готовой к публикации, если:

-   успешно регистрируется;
-   проходит полный жизненный цикл;
-   отображается в Navigation;
-   находится Search Engine;
-   содержит документацию;
-   корректно работает во всех поддерживаемых темах;
-   проходит автоматические проверки без предупреждений.

------------------------------------------------------------------------

# Итоги

Testing Showcase Studio превращает демонстрационную платформу в надёжный
элемент экосистемы UniListView. Автоматические проверки, регрессионные
тесты и интеграция с CI/CD позволяют поддерживать высокое качество
примеров и гарантировать, что каждая демонстрация остаётся рабочей,
актуальной и полезной для разработчиков.

Следующая глава будет посвящена сопровождению Showcase Studio: правилам
развития платформы, управлению версиями, депрекации сцен и долгосрочной
поддержке демонстрационной системы.
