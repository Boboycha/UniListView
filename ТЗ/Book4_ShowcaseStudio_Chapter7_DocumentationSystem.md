# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 7. Documentation System --- встроенная система документации

------------------------------------------------------------------------

# Введение

Showcase Studio является не просто коллекцией демонстраций, а
интерактивной книгой разработчика. Поэтому документация рассматривается
как полноценная часть архитектуры платформы, а не как отдельный PDF-файл
или веб-сайт.

Каждая демонстрационная сцена сопровождается встроенной документацией,
доступной непосредственно во время работы приложения.

------------------------------------------------------------------------

# Основные цели

Система документации должна:

-   объяснять назначение сцены;
-   описывать демонстрируемую возможность;
-   помогать понять архитектуру;
-   давать рекомендации по использованию;
-   предупреждать об ограничениях;
-   содержать ссылки на связанные демонстрации;
-   обеспечивать быстрый переход к исходному коду.

------------------------------------------------------------------------

# Документация как часть сцены

Каждая сцена должна содержать собственный комплект материалов.

Минимальный набор:

-   заголовок;
-   краткое описание;
-   подробное объяснение;
-   список возможностей;
-   ограничения;
-   связанные темы.

Это делает каждую сцену самодостаточной.

------------------------------------------------------------------------

# Структура документации

Рекомендуется единая структура:

1.  Назначение.
2.  Что демонстрируется.
3.  Ключевые особенности.
4.  Ограничения.
5.  Практические рекомендации.
6.  Связанные примеры.
7.  Используемые классы.
8.  Ссылки на API.

Такой формат облегчает чтение и сопровождение.

------------------------------------------------------------------------

# Markdown

Все материалы рекомендуется хранить в формате Markdown.

Это обеспечивает:

-   простоту редактирования;
-   удобное хранение в Git;
-   возможность автоматической генерации документации;
-   единый стиль оформления.

------------------------------------------------------------------------

# Интеграция с исходным кодом

Документация должна содержать ссылки на основные классы, участвующие в
работе сцены.

Например:

-   модель данных;
-   контрол;
-   renderer;
-   менеджер тем;
-   вспомогательные сервисы.

Разработчик должен быстро понимать, какие части библиотеки участвуют в
демонстрации.

------------------------------------------------------------------------

# Примеры использования

Каждая сцена должна сопровождаться короткими практическими сценариями.

Например:

-   создание списка;
-   подключение источника данных;
-   настройка колонок;
-   изменение темы оформления.

Количество примеров должно быть небольшим, но максимально понятным.

------------------------------------------------------------------------

# Предупреждения

Для потенциально опасных особенностей рекомендуется использовать
отдельные предупреждения.

Например:

> Не используйте данный режим совместно с автоматическим изменением
> высоты строк.

или

> Для виртуального режима источник данных обязан поддерживать ленивую
> загрузку.

Такие замечания помогают избежать типичных ошибок.

------------------------------------------------------------------------

# Связанные демонстрации

После изучения одной сцены пользователь должен легко перейти к
следующей.

Например:

Selection →

-   Multiple Selection
-   Keyboard Navigation
-   Touch Selection

Подобные связи превращают Showcase в последовательный учебный курс.

------------------------------------------------------------------------

# Версионирование

Если поведение сцены изменилось между версиями UniListView, документация
должна содержать соответствующую отметку.

Например:

-   Добавлено в 0.7
-   Изменено в 0.8
-   Устарело в 1.2

Это облегчает сопровождение долгоживущих проектов.

------------------------------------------------------------------------

# Поиск по документации

Поиск должен учитывать не только названия сцен, но и текст документации.

Это позволяет находить нужный пример по описанию задачи.

Например, запрос:

    drag

может вернуть сцены:

-   Drag & Drop;
-   Column Reorder;
-   Tree Drag.

------------------------------------------------------------------------

# Локализация

Документация должна поддерживать несколько языков.

При этом структура файлов остается одинаковой, а локализуется только
текст.

Это упрощает сопровождение международных версий Showcase Studio.

------------------------------------------------------------------------

# Лучшие практики

Рекомендуется:

-   использовать короткие абзацы;
-   избегать избыточной теории;
-   сопровождать описание практическими рекомендациями;
-   синхронизировать документацию с изменениями API;
-   хранить документацию рядом со сценой.

------------------------------------------------------------------------

# Антипаттерны

Следует избегать:

-   устаревших описаний;
-   копирования текста между сценами;
-   длинных теоретических разделов без практической ценности;
-   несоответствия документации и поведения демонстрации.

------------------------------------------------------------------------

# Итоги

Documentation System делает Showcase Studio полноценной интерактивной
книгой разработчика.

Вместо поиска информации на внешних ресурсах разработчик получает
объяснение непосредственно рядом с работающим примером, что значительно
ускоряет изучение UniListView и снижает количество ошибок.

Следующая глава будет посвящена системе поиска Showcase Studio,
индексированию сцен, поиску по тегам, документации и метаданным.
