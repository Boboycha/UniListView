# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 13. Designing High-Quality Showcase Scenes --- проектирование качественных демонстраций

------------------------------------------------------------------------

# Введение

Создать работающий пример значительно проще, чем создать **хорошую
демонстрацию**. Задача Showcase Studio заключается не в том, чтобы
показать, что компонент существует, а в том, чтобы научить разработчика
правильно использовать его в реальном проекте.

Каждая сцена должна быть одновременно:

-   учебным материалом;
-   эталоном качества;
-   примером архитектуры;
-   образцом оформления;
-   отправной точкой для собственного проекта.

------------------------------------------------------------------------

# Главная цель сцены

После просмотра демонстрации разработчик должен ответить на три вопроса:

1.  Что делает эта возможность?
2.  Когда её использовать?
3.  Как внедрить её в своё приложение?

Если хотя бы на один вопрос нет ответа --- сцена требует доработки.

------------------------------------------------------------------------

# Один пример --- одна идея

Наиболее важное правило Showcase Studio.

Каждая сцена должна демонстрировать **одну** основную возможность.

Хорошо:

-   Multi Selection;
-   Frozen Columns;
-   Drag & Drop;
-   Cell Templates.

Плохо:

-   Selection + Editing + Themes + Virtual Mode + Animation.

------------------------------------------------------------------------

# Обучение по шагам

Любая сложная тема разбивается на последовательность небольших сцен.

Например:

    Simple List
    ↓
    Columns
    ↓
    Selection
    ↓
    Editing
    ↓
    Virtual Mode
    ↓
    Million Rows

Такой подход позволяет постепенно наращивать сложность.

------------------------------------------------------------------------

# Минимум кода

Демонстрационный код должен быть короче производственного.

Не следует добавлять:

-   вспомогательные библиотеки;
-   лишние уровни абстракции;
-   сложные фабрики;
-   инфраструктурный код.

Каждая строка должна объяснять демонстрируемую возможность.

------------------------------------------------------------------------

# Реальные сценарии

Лучшие демонстрации основаны на задачах, встречающихся в реальных
приложениях.

Например:

-   список клиентов;
-   каталог товаров;
-   проводник файлов;
-   журнал событий;
-   история сообщений;
-   расписание.

Это делает пример узнаваемым и практичным.

------------------------------------------------------------------------

# Визуальная чистота

Сцена не должна отвлекать пользователя.

Рекомендуется:

-   одинаковые отступы;
-   аккуратное выравнивание;
-   минимум декоративных элементов;
-   отсутствие лишних кнопок;
-   понятные подписи.

------------------------------------------------------------------------

# Интерактивность

Если возможность можно изменить во время работы, пользователь должен
иметь такую возможность.

Например:

-   переключить режим;
-   изменить количество строк;
-   включить виртуальный режим;
-   изменить тему;
-   изменить масштаб.

Интерактивные демонстрации запоминаются лучше статических.

------------------------------------------------------------------------

# Самодостаточность

Каждая сцена должна запускаться самостоятельно.

Она не должна требовать:

-   предыдущей демонстрации;
-   подключения к серверу;
-   внешней базы данных;
-   специальных настроек.

------------------------------------------------------------------------

# Типичные ошибки

Наиболее распространённые проблемы:

-   слишком много возможностей одновременно;
-   длинные описания без практики;
-   отсутствие комментариев;
-   сложные тестовые данные;
-   медленная загрузка;
-   скрытые зависимости.

------------------------------------------------------------------------

# Контроль качества

Перед включением сцены в Showcase рекомендуется проверить:

-   понятность названия;
-   соответствие категории;
-   наличие документации;
-   корректность поиска;
-   отсутствие утечек памяти;
-   совместимость тем;
-   работу на всех поддерживаемых платформах.

------------------------------------------------------------------------

# Чек-лист автора

Перед публикацией новой сцены необходимо убедиться, что:

-   цель сцены очевидна;
-   код легко читается;
-   оформление соответствует стилю Showcase;
-   нет лишних элементов интерфейса;
-   документация завершена;
-   сцена проходит все внутренние проверки.

------------------------------------------------------------------------

# Рекомендации

Хорошая демонстрация:

-   открывается мгновенно;
-   выглядит профессионально;
-   объясняет идею за несколько минут;
-   может служить шаблоном для реального проекта;
-   не требует изучения исходников библиотеки.

------------------------------------------------------------------------

# Итоги

Качественная демонстрация является важнейшей частью Showcase Studio.
Именно она формирует первое впечатление о UniListView, помогает
разработчикам быстрее освоить библиотеку и задаёт единый стандарт
оформления, архитектуры и качества примеров.

Следующая глава будет посвящена тестированию Showcase Studio:
автоматической проверке демонстраций, регрессионным тестам, проверке
документации и контролю качества всей демонстрационной платформы.
