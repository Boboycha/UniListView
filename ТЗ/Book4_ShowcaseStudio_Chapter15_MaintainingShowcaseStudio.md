# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 15. Maintaining Showcase Studio --- сопровождение и эволюция платформы

------------------------------------------------------------------------

# Введение

Showcase Studio не является статическим набором примеров. Вместе с
развитием UniListView появляются новые компоненты, новые API, новые
сценарии использования и новые требования пользователей. Следовательно,
демонстрационная платформа также должна постоянно развиваться.

Главная задача сопровождения --- сохранить целостность архитектуры
независимо от количества демонстраций.

------------------------------------------------------------------------

# Основные принципы сопровождения

При развитии Showcase Studio рекомендуется придерживаться следующих
принципов:

-   единая архитектура;
-   единый стиль оформления;
-   единые правила разработки;
-   обязательная документация;
-   обязательное тестирование;
-   обратная совместимость.

------------------------------------------------------------------------

# Добавление новых сцен

Каждая новая возможность UniListView должна сопровождаться
демонстрацией.

Последовательность работ:

1.  разработка функциональности;
2.  создание сцены;
3.  подготовка документации;
4.  регистрация;
5.  автоматические тесты;
6.  включение в релиз.

Документация и демонстрация должны появляться одновременно с API.

------------------------------------------------------------------------

# Управление версиями

Каждая сцена должна иметь информацию:

-   первая версия;
-   последняя модификация;
-   совместимость;
-   статус.

Это облегчает сопровождение крупных проектов.

------------------------------------------------------------------------

# Статусы сцен

Рекомендуется использовать следующие состояния:

-   Stable;
-   Preview;
-   Experimental;
-   Deprecated;
-   Removed.

Пользователь всегда должен понимать зрелость конкретной демонстрации.

------------------------------------------------------------------------

# Deprecation

Если возможность библиотеки устаревает, соответствующая сцена не
удаляется сразу.

Рекомендуется следующий процесс:

1.  пометить как Deprecated;
2.  добавить предупреждение;
3.  предложить замену;
4.  удалить только в следующем крупном релизе.

Такой подход сохраняет совместимость документации.

------------------------------------------------------------------------

# Структура каталогов

По мере роста проекта рекомендуется придерживаться стабильной структуры:

    Showcase
    ├── Core
    ├── Packages
    ├── Scenes
    ├── Docs
    ├── Resources
    ├── Localization
    ├── Tests
    └── Tools

Это облегчает навигацию и работу нескольких разработчиков.

------------------------------------------------------------------------

# Контроль качества

Каждое изменение должно сопровождаться проверкой:

-   документации;
-   регистрации;
-   поиска;
-   локализации;
-   ресурсов;
-   тестов.

Новые возможности не должны ухудшать существующие сцены.

------------------------------------------------------------------------

# Обратная совместимость

По возможности идентификаторы сцен не изменяются.

Если переименование неизбежно, следует сохранить механизм
перенаправления со старого идентификатора на новый.

Это позволяет сохранить ссылки в документации и пользовательские
закладки.

------------------------------------------------------------------------

# Рефакторинг

При изменении архитектуры необходимо:

-   сохранить внешний контракт;
-   обновить документацию;
-   выполнить регрессионные тесты;
-   проверить производительность.

Рефакторинг не должен ухудшать пользовательский опыт.

------------------------------------------------------------------------

# Работа команды

Для крупных проектов рекомендуется разделить ответственность:

-   архитектура платформы;
-   разработка сцен;
-   документация;
-   тестирование;
-   дизайн;
-   локализация.

Чёткое распределение обязанностей ускоряет развитие Showcase Studio.

------------------------------------------------------------------------

# Подготовка релиза

Перед публикацией новой версии рекомендуется выполнить:

-   полную сборку;
-   запуск автоматических тестов;
-   проверку всех сцен;
-   проверку документации;
-   проверку поиска;
-   проверку локализации;
-   анализ производительности.

Только после успешного прохождения всех этапов формируется релиз.

------------------------------------------------------------------------

# Архивирование

Удалённые демонстрации рекомендуется сохранять в архивном пакете.

Это позволяет:

-   восстановить пример;
-   изучить старую реализацию;
-   использовать архив при миграции проектов.

------------------------------------------------------------------------

# Лучшие практики

Рекомендуется:

-   регулярно пересматривать структуру категорий;
-   объединять дублирующиеся сцены;
-   поддерживать единый визуальный стиль;
-   своевременно обновлять примеры после изменения API;
-   сопровождать каждое изменение документацией.

------------------------------------------------------------------------

# Антипаттерны

Следует избегать:

-   накопления устаревших сцен;
-   изменения поведения без обновления документации;
-   нарушения структуры каталогов;
-   публикации новых возможностей без демонстраций;
-   ручного сопровождения без автоматических проверок.

------------------------------------------------------------------------

# Долгосрочное развитие

Через несколько лет Showcase Studio может содержать сотни и даже тысячи
демонстраций.

Сохранить удобство работы помогут:

-   модульная архитектура;
-   единый Registry;
-   качественный Search Engine;
-   строгие правила разработки;
-   автоматическое тестирование;
-   регулярный аудит демонстраций.

------------------------------------------------------------------------

# Итоги

Сопровождение Showcase Studio является непрерывным процессом. Благодаря
единым правилам разработки, контролю качества, системе версионирования и
модульной архитектуре платформа способна масштабироваться вместе с
UniListView, оставаясь удобной как для пользователей, так и для
разработчиков.

Следующая глава станет заключительной и будет посвящена дорожной карте
развития Showcase Studio, перспективам расширения платформы и
рекомендациям по её использованию в коммерческих проектах.
