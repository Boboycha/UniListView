# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 3. Жизненный цикл демонстрационной сцены (Scene Lifecycle)

------------------------------------------------------------------------

# Введение

Любая демонстрационная сцена в Showcase Studio проходит строго
определённый жизненный цикл. Наличие единой модели позволяет избежать
утечек памяти, нестабильного поведения, повторной инициализации и
различий между демонстрациями.

Жизненный цикл сцены одинаков независимо от того, демонстрирует ли она
простейший список или сложную виртуальную таблицу с миллионом строк.

------------------------------------------------------------------------

# Основные состояния

    Registered
        │
        ▼
    Created
        │
        ▼
    Initialized
        │
        ▼
    Activated
        │
        ▼
    Running
        │
        ▼
    Paused
        │
        ▼
    Deactivated
        │
        ▼
    Destroyed

Каждый переход выполняется только через Scene Host.

------------------------------------------------------------------------

# Регистрация

При запуске Showcase Studio сцены **не создаются**.

Регистрация включает только описание:

-   идентификатор;
-   название;
-   категория;
-   теги;
-   версия;
-   класс сцены;
-   краткое описание.

Это позволяет загрузить каталог из сотен демонстраций практически
мгновенно.

------------------------------------------------------------------------

# Создание экземпляра

Экземпляр сцены создаётся только тогда, когда пользователь открывает её
впервые.

Создание должно быть максимально лёгким.

Конструктор не должен:

-   загружать большие наборы данных;
-   запускать таймеры;
-   обращаться к сети;
-   выполнять длительные вычисления.

Конструктор должен только подготовить внутренние структуры объекта.

------------------------------------------------------------------------

# Инициализация

После создания вызывается этап инициализации.

На этом этапе допускается:

-   создание визуальных элементов;
-   подключение обработчиков;
-   создание моделей данных;
-   подготовка тестовых данных;
-   настройка компонентов.

Именно здесь должна выполняться основная подготовительная работа.

------------------------------------------------------------------------

# Активация

После успешной инициализации сцена становится активной.

На этом этапе разрешается:

-   запуск анимации;
-   запуск таймеров;
-   запуск измерения производительности;
-   обновление интерфейса;
-   получение фокуса.

Активация должна быть быстрой.

Пользователь не должен замечать задержек.

------------------------------------------------------------------------

# Рабочее состояние

В рабочем режиме сцена полностью управляет собственным содержимым.

Она может:

-   реагировать на действия пользователя;
-   изменять данные;
-   выполнять сортировку;
-   фильтрацию;
-   масштабирование;
-   перестроение интерфейса.

При этом сцена не должна вмешиваться в работу других демонстраций.

------------------------------------------------------------------------

# Приостановка

Если пользователь временно покидает сцену, Host может перевести её в
состояние Paused.

Типичные действия:

-   остановка анимаций;
-   отключение таймеров;
-   прекращение фоновых вычислений;
-   освобождение временных буферов.

Это особенно важно для тяжёлых демонстраций производительности.

------------------------------------------------------------------------

# Деактивация

При переходе к другой сцене выполняется деактивация.

Здесь необходимо:

-   снять подписки;
-   сохранить пользовательские настройки;
-   остановить все фоновые процессы;
-   завершить измерения.

Никакие фоновые задачи не должны продолжать работать после деактивации.

------------------------------------------------------------------------

# Освобождение ресурсов

Если Host решает уничтожить сцену, вызывается этап Destroy.

Освобождаются:

-   объекты;
-   изображения;
-   кеши;
-   модели данных;
-   временные коллекции;
-   подписки.

После уничтожения сцена больше не должна использоваться.

------------------------------------------------------------------------

# Повторное открытие

При повторном открытии Host может:

1.  создать новую сцену;
2.  использовать ранее сохранённый экземпляр.

Выбор зависит от политики кеширования.

Для лёгких сцен допустимо создание нового экземпляра.

Для сложных демонстраций возможно повторное использование.

------------------------------------------------------------------------

# Взаимодействие с Scene Host

Scene Host отвечает за весь жизненный цикл.

Сцена никогда самостоятельно не уничтожает себя и не переключает другие
демонстрации.

Такое разделение обязанностей значительно упрощает архитектуру.

------------------------------------------------------------------------

# Взаимодействие с Registry

Registry предоставляет Host информацию:

-   какой класс необходимо создать;
-   как называется сцена;
-   где она расположена;
-   какие категории использует;
-   какие теги ей принадлежат.

Registry не управляет жизненным циклом.

------------------------------------------------------------------------

# Ошибки жизненного цикла

Следует избегать следующих ошибок:

-   создание тяжёлых объектов в конструкторе;
-   запуск таймеров до активации;
-   обращение к освобождённым ресурсам;
-   незавершённые фоновые задачи;
-   подписки без последующей отписки;
-   сохранение ссылок на уничтоженные компоненты.

------------------------------------------------------------------------

# Рекомендации

Для каждой сцены рекомендуется придерживаться следующих принципов:

-   минимальный конструктор;
-   быстрая инициализация;
-   явная активация;
-   корректная деактивация;
-   гарантированное освобождение ресурсов;
-   отсутствие глобального состояния;
-   независимость от других демонстраций.

------------------------------------------------------------------------

# Итоги

Единый жизненный цикл демонстрационной сцены является одной из ключевых
архитектурных особенностей Showcase Studio.

Он обеспечивает:

-   стабильность;
-   предсказуемость;
-   высокую производительность;
-   повторное использование компонентов;
-   простоту сопровождения;
-   единое поведение всех демонстраций.

Следующая глава будет посвящена системе регистрации сцен (Scene
Registry), механизмам обнаружения демонстраций, метаданным и организации
каталога Showcase Studio.
