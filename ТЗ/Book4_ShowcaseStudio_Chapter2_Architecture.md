# UniListView Developer Guide

## Book 4. Showcase Studio

# Глава 2. Архитектура Showcase Studio

## Введение

После определения философии Showcase Studio необходимо перейти к
архитектуре самой демонстрационной платформы.

Главная идея заключается в том, что **демонстрационная система должна
развиваться вместе с библиотекой**, а не существовать отдельно от неё.

Поэтому Showcase Studio проектируется как самостоятельный модуль
UniListView, имеющий собственную архитектуру, но использующий все
возможности библиотеки.

------------------------------------------------------------------------

# Основные требования

Архитектура Showcase Studio должна обеспечивать:

-   единое приложение;
-   динамическую регистрацию демонстраций;
-   отсутствие жёстких зависимостей между сценами;
-   возможность добавления новых примеров без изменения существующих;
-   единый жизненный цикл всех демонстраций;
-   единый стиль оформления;
-   встроенную документацию;
-   встроенную систему поиска;
-   поддержку диагностики и профилирования.

------------------------------------------------------------------------

# Логическая структура

    Showcase Studio
    │
    ├── Core
    ├── Navigation
    ├── Scene Registry
    ├── Scene Host
    ├── Documentation
    ├── Diagnostics
    ├── Search
    ├── Themes
    └── Demo Packages

Каждый модуль отвечает только за свою область ответственности.

------------------------------------------------------------------------

# Core

Core является центральной частью Showcase Studio.

Он управляет:

-   запуском приложения;
-   загрузкой настроек;
-   регистрацией сцен;
-   переключением демонстраций;
-   глобальными сервисами;
-   жизненным циклом приложения.

Core никогда не содержит конкретных демонстраций.

Он знает только интерфейсы.

------------------------------------------------------------------------

# Scene Registry

Registry представляет собой каталог всех доступных демонстраций.

Каждая сцена регистрируется автоматически.

Например, при запуске приложение получает список:

-   Basic List;
-   Selection;
-   Columns;
-   Editing;
-   Virtual Mode;
-   Themes;
-   Performance;
-   Diagnostics.

Registry не создаёт сцены заранее.

Он лишь хранит информацию о них.

------------------------------------------------------------------------

# Scene Host

Host отвечает за размещение текущей сцены.

Он:

-   создаёт экземпляр сцены;
-   размещает её внутри рабочей области;
-   освобождает ресурсы;
-   переключает демонстрации;
-   управляет навигацией назад и вперёд.

Таким образом каждая сцена полностью изолирована.

------------------------------------------------------------------------

# Навигация

Навигация не знает деталей реализации сцен.

Она оперирует только идентификаторами:

-   категория;
-   имя;
-   путь;
-   теги.

Это позволяет менять внутреннюю реализацию демонстраций без изменения
пользовательского интерфейса.

------------------------------------------------------------------------

# Документация

Каждая сцена сопровождается встроенным описанием.

Описание содержит:

-   назначение;
-   объяснение;
-   особенности;
-   ограничения;
-   связанные примеры;
-   ссылки на исходный код.

Таким образом документация становится частью Showcase Studio.

------------------------------------------------------------------------

# Изоляция демонстраций

Ни одна демонстрация не должна напрямую зависеть от другой.

Если сцена удалена, остальные продолжают работать.

Это обеспечивает простое сопровождение проекта и независимую разработку
новых примеров.

------------------------------------------------------------------------

# Расширяемость

Добавление новой демонстрации должно сводиться к трём шагам:

1.  Создать класс сцены.
2.  Зарегистрировать её.
3.  Добавить описание.

Никаких изменений существующего кода быть не должно.

------------------------------------------------------------------------

# Итоги

Архитектура Showcase Studio строится вокруг идеи слабой связанности.

Core управляет системой.

Registry знает о существующих сценах.

Host отображает текущую сцену.

Навигация позволяет быстро находить нужный пример.

Документация превращает каждую сцену в полноценный обучающий материал.

Такая архитектура позволяет годами развивать библиотеку без превращения
демонстрационной системы в хаотичный набор примеров.
