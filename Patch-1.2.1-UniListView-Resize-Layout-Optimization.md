# Patch 1.2.1 — UniListView Resize/Layout Optimization

## Цель

Оптимизировать цепочку `Resize → InvalidateLayout → Paint → EnsureLayout → RecalculateLayout` в `TUniListView` без изменения внешнего поведения компонента.

Основная задача — сократить лишние пересчёты layout, измерения текста и повторные repaint во время изменения размера формы или самого списка, особенно на FMX Linux.

Поведение, внешний вид и публичный API `TUniListView` изменять запрещено.

---

## Основание

Текущая цепочка resize выглядит так:

```text
TUniListView.Resize
    ↓
InvalidateLayout
    ↓
Redraw
    ↓
Paint
    ↓
EnsureLayout
    ↓
RecalculateLayout
    ↓
PrepareTextLayouts
    ↓
Draw...
```

При `AutoCardHeight` дополнительно используется отложенный пересчёт:

```text
Resize
    ↓
облегчённый layout / reuse старых высот
    ↓
ResizeHeightTimer
    ↓
сброс кэша text-layout
    ↓
InvalidateLayout
    ↓
повторный полный layout + paint
```

Во время непрерывного изменения размера Linux может получать большое количество промежуточных layout/paint-циклов.

---

# Задачи

## 1. Проверка фактического изменения размера

В `TUniListView.Resize` не запускать layout invalidation, если фактические размеры клиентской области не изменились.

Добавить внутреннее хранение последнего обработанного размера:

```text
FLastLayoutWidth
FLastLayoutHeight
```

или эквивалентную структуру.

Сравнение выполнять с учётом допустимой погрешности FMX.

Если ширина и высота не изменились:

- не помечать layout dirty;
- не перезапускать resize timer;
- не вызывать `Redraw`.

---

## 2. Разделить геометрический и текстовый layout

Не выполнять полный сброс text-layout при каждом промежуточном resize, если это не требуется.

Разделить invalidation минимум на два уровня:

```text
Geometry dirty
Text metrics dirty
```

или использовать уже существующие флаги/кэши, если архитектура это позволяет.

При изменении только размера viewport:

- пересчитать видимую область;
- scrollbar geometry;
- clip bounds;
- positions;

но не пересоздавать text-layout, если ширина текстового блока фактически не изменилась.

---

## 3. Проверка изменения ширины текстового контента

Перед сбросом:

- `FPreparedCardWidth`;
- `FPreparedTextWidth`;
- кэшей высот;
- подготовленных text-layout;

сравнить старую и новую эффективную ширину текста.

Если эффективная ширина не изменилась, не сбрасывать кэши.

Учитывать:

- padding;
- card margins;
- column widths;
- scrollbar width;
- frozen columns;
- icon/action areas;
- режим отображения списка или карточек.

---

## 4. ResizeHeightTimer

Таймер отложенного пересчёта должен запускаться только тогда, когда:

- `AutoCardHeight` действительно требует повторного измерения;
- изменилась эффективная ширина текста;
- существует контент, высота которого зависит от wrapping.

Не перезапускать таймер без необходимости.

Если таймер уже ожидает выполнение и новый resize не изменил эффективную ширину текста, не менять его состояние.

После выполнения таймера:

- один раз сбросить только необходимые кэши;
- один раз вызвать layout invalidation;
- не допускать дополнительного `Redraw`, если он уже будет вызван через invalidation.

---

## 5. Устранить двойной Redraw

Проверить цепочку:

```text
Resize
    ↓
InvalidateLayout
    ↓
Redraw
```

и все вызываемые методы.

Не допускать ситуации, когда один resize приводит к нескольким последовательным:

```text
InvalidateLayout
Redraw
Repaint
```

Если `InvalidateLayout` уже гарантирует repaint, не выполнять дополнительный repaint отдельно.

---

## 6. RecalculateLayout

Добавить ранние выходы для случаев, когда:

- размеры не изменились;
- layout уже актуален;
- нет элементов;
- режим отображения не требует пересчёта;
- изменилась только scroll position;
- изменился только viewport clip.

Не выполнять повторное выделение динамических массивов, если их размер не изменился.

По возможности переиспользовать:

- массивы layout-данных;
- массивы высот;
- text-layout объекты;
- временные буферы.

---

## 7. PrepareTextLayouts

Не пересоздавать text-layout для элемента, если не изменились:

- текст;
- шрифт;
- font size/style;
- text color, если layout от него не зависит;
- максимальная ширина;
- wrapping mode;
- alignment;
- DPI/scale.

Использовать существующие кэши либо расширить их минимально.

Не менять внешний API.

---

## 8. Scroll и resize — разные invalidation

Проверить, не вызывает ли изменение scroll position полный layout.

Scroll должен по возможности:

- обновлять только visible range;
- менять drawing offset;
- выполнять repaint;

без полного `RecalculateLayout`, если размеры и данные не изменились.

---

## 9. Columns и card mode

Для list mode:

- не пересчитывать все колонки, если изменилась только высота viewport;
- не запускать `RebuildFilter`;
- не запускать сортировку;
- не запускать tree rebuild.

Для card mode:

- пересчитывать wrapping и auto-height только при изменении эффективной ширины карточки;
- не сбрасывать высоты при изменении только высоты viewport.

---

## 10. BeginUpdate / EndUpdate

Проверить внутренние resize/layout операции на возможность группировки.

Разрешается использовать существующий механизм `BeginUpdate/EndUpdate` или внутренний счётчик блокировки invalidation, если это не меняет публичное поведение.

Во время одной внутренней операции разрешён только один финальный:

```text
InvalidateLayout
```

и один repaint.

# Диагностика

Разрешается временно добавить внутренние счётчики:

```text
ResizeCount
LayoutInvalidationCount
RecalculateLayoutCount
PrepareTextLayoutsCount
RedrawCount
ResizeHeightTimerCount
```

Диагностика должна:

- быть пассивной;
- не менять ветвление;
- не влиять на timing;
- быть отключаемой;
- не добавляться в published API.

После завершения Patch можно оставить её только под условной компиляцией.

# Критерии приёмки

Patch считается выполненным, если:

1. Поведение и внешний вид не изменились.
2. Публичный API не изменён.
3. Один resize не вызывает повторных одинаковых layout invalidation.
4. Изменение только высоты viewport не сбрасывает text-layout без необходимости.
5. ResizeHeightTimer не запускается, если эффективная ширина текста не изменилась.
6. Scroll не вызывает полный layout без необходимости.
7. Количество `RecalculateLayout` во время непрерывного resize уменьшено.
8. Количество `PrepareTextLayouts` во время непрерывного resize уменьшено.
9. Все существующие regression-сценарии проходят.
10. Код остаётся совместимым с FMX Windows и Linux.
11. Файлы сохраняются в UTF-8 BOM и CRLF.
12. Не используется `with`.
13. В коде нет magic numbers.
14. Используются guard clauses.
15. Если изменяется `UniList.Columns.pas`, `System.UITypes` остаётся в `uses`.
