# Patch 1.1.1 --- Automatic Regression Runner

## Цель

Доработать существующий проект **UniPopupPerformanceLab**. Не создавать
новый проект и не выполнять рефакторинг архитектуры.

Основная задача --- превратить лабораторию в автоматический
регрессионный стенд, выполняющий полный набор сценариев без участия
пользователя и формирующий единый отчёт.

------------------------------------------------------------------------

## Ограничения

-   Не менять архитектуру проекта.
-   Не удалять существующий ручной режим.
-   Не менять существующие метрики и счётчики.
-   Не менять существующие тестовые компоненты.
-   Не изменять код UniListView ради лаборатории.
-   Все новые возможности должны быть расширением существующего проекта.

------------------------------------------------------------------------

## 1. Automatic Runner

Добавить кнопку:

``` text
Run Full Matrix
```

При запуске пользователь больше ничего не переключает вручную.

Лаборатория должна самостоятельно выполнить все сценарии.

------------------------------------------------------------------------

## 2. Scenario Engine

Убрать перебор через комбинации:

-   Test Mode
-   Popup State
-   Popup Content

Вместо этого создать явный список сценариев.

Каждый сценарий представляет собой полностью определённое состояние.

Например:

-   Baseline
-   DropDown / No PopupComponent
-   DropDown / Popup assigned / Closed
-   DropDown / Popup Open
-   DropDown / Closed After Open
-   DropDown / Detached
-   Lookup / Empty
-   Lookup / 10 items
-   Lookup / 1000 items

Добавление нового сценария должно требовать регистрации только одного
объекта сценария.

------------------------------------------------------------------------

## 3. Scenario Lifecycle

Каждый сценарий обязан выполняться по одной схеме:

``` text
Destroy previous controls

↓

Create controls

↓

Configure scenario

↓

ProcessMessages

↓

Wait stabilization

↓

Reset counters

↓

Measurement

↓

Save result

↓

Destroy controls

↓

ProcessMessages

↓

Next scenario
```

Каждый сценарий должен стартовать с полностью чистого состояния.

------------------------------------------------------------------------

## 4. Stabilization

Время стабилизации должно задаваться одной константой.

Перед измерением обязательно выполнить:

-   ProcessMessages
-   Delay
-   ProcessMessages

------------------------------------------------------------------------

## 5. Runtime Validation

Лаборатория должна проверять корректность собственного состояния.

Если сценарий называется:

    Popup Detached

то обязательно:

    Parent = nil

Если нет --- сценарий получает статус:

    FAILED

Аналогично проверять:

-   Popup Closed
-   Popup Open
-   Popup Assigned
-   Popup Detached

Если фактическое состояние не соответствует сценарию --- это ошибка
теста.

------------------------------------------------------------------------

## 6. Runtime State

Добавить вывод:

-   Popup exists
-   Parent class
-   Parent=nil
-   Visible
-   AbsoluteVisible
-   Scene assigned
-   Root assigned
-   Attached to visual tree
-   PopupHost assigned
-   Popup currently open

Использовать реальные значения, а не сокращённые флаги.

------------------------------------------------------------------------

## 7. Assertions

При невозможных состояниях:

-   Detached + Parent\<\>nil
-   Closed + participates in scene
-   Closed + Popup Paint \> 0
-   Detached + Paint \> 0

сценарий должен быть отмечен как FAILED.

Выполнение остальных сценариев продолжается.

------------------------------------------------------------------------

## 8. Unified Report

Создавать один файл отчёта.

Структура:

-   Заголовок
-   Scenario
-   Runtime State
-   Metrics
-   Validation
-   Result

В конце обязательно добавить сводную таблицу:

| Scenario \| PASS \| Avg \| P95 \| Max \| Popup Paint \| Popup Realign
  \| Notes \|

И общий итог:

-   Executed
-   Passed
-   Failed
-   Skipped
-   Total duration

------------------------------------------------------------------------

## 9. Acceptance

Patch считается выполненным если:

-   автоматический запуск работает;
-   ручной режим сохранён;
-   сценарии выполняются без участия пользователя;
-   каждый сценарий стартует с чистого состояния;
-   невозможные состояния автоматически обнаруживаются;
-   создаётся единый отчёт;
-   существующий функционал лаборатории сохранён.

------------------------------------------------------------------------
